# B1 V5.6 verification

Built the real pi32v2 AC791N application, 90,628 bytes; 490,936 bytes XIP headroom.
Pool ends at 0x01C4F244, below the stack guard at 0x01C74000.
Product identity remains FM-1_481026. Protected boot bytes are unchanged.

Production OTA core and trusted application-only loader are ported from the
attached RUPTURE V1.52. App-only updates preserve flash 0..0x3FFF.
V15 full-flash installation requires the original pinned flash and loader,
plus the protected-boot comparison used by RUPTURE.

The original B1 V5.5 core rejects the supplied original V15 with -3 before
any erase. The V5.6 core accepts the same exact original file in simulation.
The reported self-update failure could not be reproduced on a blank simulated
stage with V5.5; that test passes. Device-specific staging state and USB timing
were not available for inspection. V5.6 replaces the stricter residual loader
checks and the alternate loader execution path with RUPTURE's implementation,
and removes reentrant USB polling from the main-loop OTA idle hook.

17 production-core SysEx/NOR replay cases pass: B1 V5.6 self-update, B1 V5.5,
BEETLE RC1.01, RUPTURE V1.52, original V15, each with blank or residual staging;
missing success handshake, user abort, flash erase failure, corrupt readback,
unknown nonblank staging, invalid app CRC with valid wrapper, bad payload CRC.
Successful community cases verify exact built-in staged loader and 015 identity.
Original V15 uses the exact incoming pinned vendor loader.

WebInstaller JavaScript parses; embedded firmware bytes and SHA-256 match.
No physical hardware flashing, reboot, USB timing or final install was tested.
Host commit success is not proof of a completed physical firmware installation.

Bootstrap: if V5.5 refuses the fixed package, use the existing OCT-minus boot
path and a compatible FM1 updater. REC silent boot can retry but still executes
the old OTA validation code. The new image cannot patch an old running updater.
