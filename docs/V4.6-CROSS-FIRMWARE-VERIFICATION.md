# B1 V4.6 — Native OTA compatibility verification

Date: 2026-10-22. **Product/USB identity: `FM-1_2147` unchanged from V4.5.** The version label V4.6 is independent of this identity and MUST NOT change it in future builds.

## Audited root cause

The old V4.3 firmware rejected foreign APP_ONLY packages when the protected 0x0000–0x3FFF boot header differed (`-5`) or an incoming loader did not match its one pinned executable (`-16`). V4.4 allowed different loader bytes and ignored non-programmed boot headers, but it *did not independently verify the incoming loader's entire body CRC16 nor its versioned Felucca-family marker*. This accepted corrupted or non-family loader bodies when the surrounding UFW CRC had been recomputed.

## V4.6 correction

- Keep the V4.4/V4.5 native `APP_ONLY` validation: AC791N, chip key 0x980F, app at 0x4000/XIP 0x02000120, inner app directory and decoded app CRC checks.
- Verify both UFW payload CRCs **and** version-tagged incoming Felucca loader structural header, loader entry 0x01C0A800, its staging-size bound, marker `FELUCCA-LOADER-1` in the executable prologue, and **full body CRC16** before touching OTA flash.
- Recognize different compiled loader bodies; do not require their SHA to equal one previously built loader. CRC16 and a version tag are structural checks, NOT cryptographic authentication. The Firmware Hub must obtain verified original distribution packages and pin SHA-256. Known loader bytes retain B1's byte-pinned APP_ONLY writer. A different versioned/CRC-verified Felucca-family loader is staged from the incoming verified package so it can support a compatible second-stage update. This is a trust decision based on the Hub delivering a SHA-256-pinned original release; the firmware alone cannot authenticate a forged tag+CRC. The UPDATA_PARM handoff marker remains `ota-FM-1_015`; the host must re-detect the actual loader identity (including supported `ota-FM-1_9xx` devices) before WRITE.
- Read back every byte of the staged loader, CRC16-check the actual staging contents, require the exact host `success` response before UPDATA_PARM commit.
- Preserve stock V15's separate, exact SHA-pinned full-flash route. It is NOT a generic full-flash updater.
- Staging erases/writes are restricted to the existing OTA region 0xE0000–0xE4FFF. Projects/recovery data and protected boot are never erased by B1's stage adapter. Power-loss safety of the second-stage executable has not been proven.

## Native packet-level replay (production `firmware/ota.c`)

Run `python tests/run_ota_v46_replay.py cc`. Test fixtures are the **original, byte-preserved B1 V4.6 package and BEETLE RC1.01 package**, plus fully recalculated, checksum-consistent mutations. This is NOT a claim of original Felucca 1.6 / Felucca 1.1.5 / BEETLE V1.4.14 coverage or on-device flashing. Passing a mutated-loader replay shows acceptance of a second compiled form but not authenticity or safe arbitrary loader execution.

Positive cases: B1 V4.6→B1, B1 V4.6→B1 V4.5 rollback (same package identity), B1 V4.6→BEETLE RC1.01, foreign protected bootheader (APP_ONLY), different valid recompiled Felucca-family tagged loader, and larger compatible loader with full-length staging verification. Optional extra original `.fwsc` files can be passed as additional arguments.

Rejected *without staging erase*: corrupt loader with recalculated outer UFW checksums, forged non-family marker, oversized loader, bad application CRC, wrong chip configuration, overlapping UFW entries, early cancellation. Additional cases: flash readback corruption and absent `success` reply cause **no commit**; simulated staging erase failure causes **no commit**.

## Existing functionality

The `b1_engine.c`, `b1_performance.c`, `b1_storage.c`, `b1_ui.c`, `usb.c` and `b1_ota_target.c` files remain **byte identical** to V4.5. Sound, USB endpoints and scan timing have not been deliberately altered. The native firmware and WebInstaller share one pinned FWSC binary. The package identity is not bumped to `FM-1_2148`.

## Not verified — do not report as proven

- Actual The Firmware Hub end-to-end B1 V4.6→Felucca 1.6/1.1.5 or BEETLE V1.4.14→B1 transitions, because those untouched release packages were not supplied in this build.
- Physical FM1 flashing/reboot/re-flashing back, original vendor stock V15 restore, or USB disconnect under a real device.
- The safety of every foreign firmware's memory map, installed loader, or project storage when the second-stage loader executes. CRC and structural compatibility checks are NOT general executable code authentication.
- New physical CPU/DMA measurements or a verified fix for V4.5's reported polyphony crackling.

A valid independent recovery path and backup remain necessary before flashing experimental firmware.
