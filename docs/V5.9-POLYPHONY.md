# V5.9 polyphony measurements

The AC791N firmware, pinned installer and release tests were built from the delivered V5.8 project. The hardware playback profile, 12 voices, nine drawbars, sample rate, block size and effect algorithms are preserved.

## Software performance

V5.9-HOST-POLYPHONY.csv contains all 32 comparisons. Each timed workload renders the same 256-frame stereo block after restoring the same engine state. The tests cover three, six, nine and twelve voices in ORGAN and SAW with ROCK, rotary, scanner, delay, reverb and percussion enabled. The attack block starts on note-on. The sustain block follows 160 blocks of warm-up. Release begins when all keys lift. The changes workload releases alternate notes, advances 39 frames, moves a drawbar and adds a new note.

Each figure is the median of eight run averages on a single pinned x86-64 Linux CPU, measured using thread CPU time. Each average includes 320 renders. Compiler flags and inputs were identical, and execution order alternated between runs. Restore and setup time are excluded. These figures describe typical DSP render cost on the test computer. They measure neither worst-case interrupt latency nor FM1 DMA misses.

| Twelve voices | ORGAN, reduction in render time | SAW, reduction in render time |
| --- | ---: | ---: |
| Attack | 3.8% | 3.9% |
| Sustain | 21.9% | 34.5% |
| Release | 42.9% | 19.5% |
| Changes | 27.8% | 14.5% |

## Correctness

The pinned V5.8 engine and V5.9 engine produced identical stereo PCM and full engine-state digests in all 32 benchmark workloads and 64 additional sequences of 100 blocks each. These exercise irregular render lengths, phase-clock wrap, both DSP profiles, partial releases, note stealing and oscillator changes. The 320 earlier PCM/state regression cases passed. The remaining release tests cover DAC packing, flash compatibility, project persistence, the actual packaged firmware, SHA-pinned installer and host OTA replay. See V5.9-OFFLINE-TEST-LOG.txt.

Rebuild using docs/BUILD-V5.9.md. Run python3 tests/measure_v59_poly.py on Linux to repeat the timing comparison.

## FM1 verification

The physical FM1 was unavailable. For a device comparison, use the same saved registration and MIDI performance under each version. Open SCL / SCALE, then SELECT to open AUDIO DIAG. Leave TEST TONE off. Record the change in DMA MISSES and the PEAK value through sustained chords, rapid releases and retriggers. At 44.1 kHz, the 256-frame half-buffer lasts 5.805 ms. The pre-copy software guard is 5.500 ms. Record the stereo output to check for clicks and dropouts. Actual flash saves retain the existing codec pause.
