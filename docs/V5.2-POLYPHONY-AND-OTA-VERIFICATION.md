# B1 V5.2 — Lossless Leslie and ROCK optimization: verification

**Date:** 2026-11-02. **Permanent identity:** `FM-1_481026`.

## Actual native changes (relative to V5.1)

- `firmware/b1_engine.c`: share four FULL-mode Leslie sine LUT samples between Doppler delay and stereo gain calculations. Delay ages, phases, integer rounding and signal flow are unchanged.
- `firmware/b1_engine.c`: replace 64-bit arithmetic with **mathematically identical bounded 32-bit arithmetic** for common ROCK drive, sag, cabinet mix and clean/ROCK crossfade values, retaining the original 64-bit path for extreme inputs.
- Existing reverb already uses once-per-block prepared coefficients and exact reciprocal/correction. No speculative reverb rewrite was accepted; no measured reverb speedup claimed.
- The SAFE low-cost FM1 engine, FX algorithms, 91 tonewheels, 12 voices, registrations, percussion, autosave, project sectors, native OTA, USB identities, DMA and boot header are unchanged.
- `firmware/b1_main.c`: version/physical-hardware caveat comment only. README and CHANGELOG updated.

## Verified on host and with native target builder

- 96 polyphony cases, 128 note-transition/control-gesture cases, and 96 full DSP (including Leslie, ROCK, reverb, scanner, delay) cases: **320 bit-for-bit identical stereo PCM + entire `struct b1_engine` states versus V5.1**.
- **1,500,000 arithmetic comparisons** with original signed 64-bit operations, covering safe fast paths and extreme-value fallbacks.
- 72 audio combinations: no sample hard-clipped to int16 extremes in the host test; 48 DMA chunk consistency comparisons pass.
- JieLi AC791N/pi32v2 toolchain native ELF and complete `.fwsc` successfully built.
- Package identity, UFW/app/OTA wrapper integrity and SHA-256 embedded WebInstaller package checks pass.
- Two native CHECK → READ → `success` → stage/readback → commit OTA smoke fixtures pass (B1 and original BEETLE). Full 16-case cross-firmware suite not rerun. No change was made to the native OTA implementation.

## Performance limits and honest interpretation

Host-only x86 mixed-effects benchmarks were noisy: repeated short runs with SAFE and FULL DSP showed gains and losses between runs. **No reproducible percentage performance gain can be claimed yet**, and x86 timing is not a proxy for pi32v2 cycle counts. Native assembly supports the intended avoidance of 64-bit intermediate calculations for bounded common ROCK values, but the exact benefit remains unmeasured on real hardware.

The user confirms earlier B1 releases run on **a physical FM1**. This V5.2 build has **not** been individually tested on a physical FM1 by the assistant; 12 voices with all FX / SAW / ROCK and 25% headroom **remain unproven**. The fixed identity is `FM-1_481026`.

## Hardware test protocol

1. Make a reliable backup and verify independent recovery before firmware transfer.
2. On real FM1 open **SCL / SCALE → SELECT → AUDIO DIAG**.
3. Compare V5.1 and V5.2 under exactly the same settings, volume, power and USB conditions: 3, 6, 9 and 12 notes; B3 and ROCK; ORGAN and SAW; scanner, Leslie, delay and reverb; leakage, percussion and click on/off.
4. Measure maximum `PEAK` render time and **DMA MISSES**. Aim for PEAK ≤ 4,125 µs and DMA MISSES = 0 under sustained worst-case; the firmware has a 5,500 µs internal hard budget for each 256-frame DMA half-buffer.
5. If crackle persists without DMA MISSES, check analog output overload and power/noise separately. Never claim clipping is fixed solely from digital host tests.
6. Separately test The Firmware Hub B1 → other verified compatible FM1 firmware → B1, because OTA compatibility is not proven by two synthetic/protocol smoke fixtures.

**Verdict:** sound-equivalent source and a valid native release; no honest physical worst-case headroom or fully working cross-firmware Hub round-trip claim yet.
