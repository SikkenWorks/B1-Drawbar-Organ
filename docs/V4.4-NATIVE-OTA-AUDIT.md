# B1 V4.4 · Native cross-firmware OTA audit

Audit source: `FM1-CROSS-FIRMWARE-OTA-AUDIT-BEETLE-B1-NERVE.md` (provided by user).
Scope: installed **B1 firmware** and its actual C updater. The BEETLE target package was checked; **BEETLE and NERVE installed native updaters were not audited**, because this release does not contain their current corresponding native source and binaries.

## Confirmed pre-fix defects (native B1 V4.3)

1. Native `firmware/ota.c` compared every byte of incoming `flash.bin[0..0x3fff]` with the currently installed boot sector, returning `-5` on differences. This wrongly barred valid APP_ONLY transfers even when the protected sector would not be written.
2. The code required the incoming `ota.bin` body to be byte-identical with one pinned loader (or the separately approved official V15 case), returning `-16` for every other loader, even for potentially compatible APP_ONLY packages.
3. It did not validate the incoming AC791N chip key, XIP app directory and `app.bin` CRC before staging, allowing coherent UFW containers with damaged app data to proceed to commit.

Baseline **actual C updater** native packet-replay outcomes: differing protected header → `-5`, foreign loader → `-16`, coherently wrapped corrupt app → incorrectly committed. These were reproduced with exact original B1/BEETLE payloads and checksum-valid test mutations, not inferred from a JavaScript WebInstaller.

## V4.4 changes in firmware/ota.c

- UFW: enforce AC791N signature, exact two supported entries, bounded offsets/sizes, checksums of both complete payloads, no overlaps and no duplicate file types.
- APP_ONLY: require chip key `0x980f`, `app_area_head` at `0x4000`, XIP address `0x02000120`, `app.bin` at `0x120`, 0x8DFBC slot, valid app-area descriptor CRCs and **decoded application data CRC**. Different boot bytes are allowed only because the app-only loader never writes them.
- APP_ONLY: **never stage or run the untrusted incoming loader**. Load the exact source-included, byte-pinned 6,898-byte B1/Felucca compatible loader instead, read back and compare all bytes.
- FULL_FLASH: keep a separate, exact-hash-gated original official M-VAVE V15 restore route; do not make arbitrary full-flash images flashable.
- Stage only after all CHECK validation; require 8-byte `success` reply to `0xE0000000` and a verified UPDATA_PARM before commit. Keep B1-only project sectors outside staging. Cancel/error path prevents commit and attempts staging cleanup.
- Loader identity in the commit record remains `ota-FM-1_015`, the identity of the **actual pinned loader**, not the incoming untrusted package.

## Limits / do not claim

- The **original unchanged Felucca v1.6/v1.1.5** packages are not included and were NOT replayed. Provide them as additional command-line inputs to the replay test, then investigate any errors. The synthetic foreign-loader test is not proof of their original format.
- The genuine official M-VAVE V15 full restore package was not supplied for this iteration. Its independent native FULL_FLASH path was **not exercised** in this replay matrix.
- USB reenumeration, flash hardware timing, power cuts, live audio/USB behavior, actual boot and the ability to switch *back* on physical FM1 are unverified.
- A successful C replay is NOT proof that the FM1's SPL loader can install each foreign firmware, or that the destination app's ROM/SDK assumptions are all compatible. No claim of universal updater support.
- The previously installed B1 V4.3 remains subject to its old native checks until a V4.4 installation really succeeds. A fixed WebInstaller alone does not fix the installed C updater.

**Hardware sign-off requires** B1 V4.4 install, a native direct switch from B1 to a separate **exact, original** tested compatible firmware and a successful return to B1, with complete device identity/readrequest/status logs and verified data backup/recovery.
