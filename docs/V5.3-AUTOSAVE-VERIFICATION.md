# B1 V5.3 — AUTO SAVE control and verification

## Behaviour

- Default is **OFF**, including an installed legacy V4.9–V5.2 journal.
- SAVE / PROJECT MENU: turn encoder **K4 right** to enable, **left** to disable.
- AUTO SAVE ON saves parameter snapshots after five seconds with no edits and when all keys, oscillators, percussion, delay and reverb tails are silent. Existing 60s wear throttling applies to routine autosave.
- AUTO SAVE OFF performs **no background snapshot writes** and does **not automatically restore** the prior live snapshot. Manual SAVE and LOAD of 12 project slots remain fully available.
- ON/OFF changes are effective immediately in RAM, but persisted after 5 seconds with no changes and audio silence; UI shows `SETTING PENDING` until the flash commit. Powering off too soon will retain the previous disk setting.
- No sector allocation changes: existing two-bank journal, archive schema **3**, names and saved projects remain byte-layout compatible. The previously unused header offset **28..31** stores ON token `0xA5073AD5` (others including legacy 0xFFFFFFFF default OFF). Journal commit and readback remain guarded.
- REC startup continues to bypass project flash. No modifications to audio, MIDI, OTA code, or external storage.

## Native build

- JieLi pi32v2 native target compiled: `build/B1.elf`, `_start=0x02000120`, `build/B1-app.bin`.
- Signed/structured OTA container: `build/SikkenWorks-B1-V5.3.fwsc`, **610086 bytes**.
- **Unchanged identity:** `FM-1_481026` in native USB-MIDI application and FWSC.
- FWSC SHA-256: `16680dbfba8bc80dc235f04845090a0c3fb477ceb4c4b5cc4f76096e6ff279be`.
- WebInstaller embedded data is exactly byte-identical to the firmware, SHA-256 matched.

## Regression tests (executed)

- Native storage simulation: legacy schema-3 journal OFF by default, ON/ OFF journal readback, incomplete-write fallback, 12 stored projects intact, non-owned sectors untouched.
- Native renderer: separate AUTO SAVE OFF, ON and SETTING PENDING frames differ as expected.
- 320 lossless stereo PCM and complete engine state comparisons against V5.1; new V5.3 changes **no audio code** from V5.2.
- Additional 96 + 128 exact baseline PCM/DSP cases, 72 stress configurations, 48 DMA block-equivalence cases, 1.5 million bounded arithmetic checks.
- 2 native OTA CHECK/staging/success/commit smoke scenarios with available original reference firmware packages.
- Native target firmware, app CRC, package/loader checksum, and installer embed/hash checked.

## Unproven hardware scenarios

- AUTO SAVE K4 control, flash commits and reboot persistence have **not** been tested by this release process on a physical M-VAVE FM1.
- B1 has previously been tested on actual FM1 hardware, but V5.3 full 12-voice realtime headroom, headphone crackle and B1 → Felucca → B1 hardware transitions remain **unverified**.
- Hardware flashing should be performed only with a known-good backup and independently tested recovery route.
