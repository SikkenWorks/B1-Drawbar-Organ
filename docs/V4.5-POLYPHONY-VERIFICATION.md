# SikkenWorks B1 V4.5 — Polyphony DSP Verification

## Reason for this release

Physical FM1 feedback on B1 V4.4: previous severe square-like output appears absent, but audible crackling begins near **three simultaneous notes**. Such crackling may result from audio DMA deadline misses, audio clipping, amplifier/output limitations, or multiple effects sharing CPU. The exact cause has **not yet been isolated from a hardware timing log**. V4.5 reduces known work in the three-plus-voice engine but is **not yet a physically verified crackle fix**.

## Native target and package

- Target: M-VAVE FM1 AC791N, JieLi pi32v2 at 44.1kHz stereo, 128-frame DMA halves.
- Product identity: `FM-1_2147`.
- Standalone firmware: `build/SikkenWorks-B1-V4.5-BEETLE-OTA.fwsc`.
- Size: 610,086 bytes.
- Firmware SHA-256: `5db2b5de7ec408be9ba0c279c7ab588e4cdcfcecd8bd2292a2602b97da2ee264`.
- Target application: `build/B1-app.bin` (85,092 bytes).
- The protected initial 16,384 flash bytes are byte-identical to the validated BEETLE reference and V4.4. OTA loader remains the pinned reference body, not an unknown executable.
- The installer embeds byte-for-byte the above FWSC with matching product ID and SHA-256 and keeps the source-firmware SLOOP/Felucca HF2 route.

## Exactly what changes

1. **Dense shared-tonewheel progression:** In the >=3 settled voice case, the wheel index list is already unique. On chunks without wheel-frame wrap, align each used wheel's lazy phase to the frame at chunk entry, then increment a single step per frame. Eliminate redundant per-wheel memo read/compare in the hot loop. Update cached samples and, for active percussion, all stamps identically to V4.4. With no active percussion, publish stamps once per chunk instead of twice per wheel per sample. All 91 potential wheels continue logically free-running.
2. **Percussion bus:** Exact algebraic replacement of the old `int64_t` product division by 260,000 using unsigned 32-bit limbs and a 32-bit division by 8,125. The original signed 64-bit implementation remains as an out-of-bounds fallback. This retains the one-envelope percussion bus shared by all held UPPER notes.
3. **Voice envelope:** Exact 32-bit envelope multiplication for settled ORGAN/SAW waveforms under the proven voice-sum bounds. Original 64-bit multiplication is retained throughout oscillator crossfade where rare large intermediate values are possible.
4. **Retained exactly:** Full polyphony limit 12, nine harmonic drawbars, phase model, key click, release clicks, leakage, ROCK/LORD, B3/Leslie, scanner, delay, reverb, all project data, MIDI/chord assignments/LEDs and native OTA protections.

## Host regression results

- `tests/native_v45_poly_exact.c`: reference `tests/reference_v41/b1_engine.c` is the same immutable sound engine as V4.4. The full PCM stream and complete `struct b1_engine` internal state are bitwise identical in **96 stress scenarios**: 1 through 12 voices, eight combinations of full/safe DSP and ORGAN/SAW/B3/ROCK, including maximal click, leakage, nine open drawbars, releases, heavy FX and silence cleanup.
- `tests/native_v45_exact_percussion.c`: **2,000,285** signed/divisor comparisons to original 64-bit formula, exact. The same test also passed with AddressSanitizer and UndefinedBehaviorSanitizer.
- `tests/native_v41_idle_compare.c`: **four scenarios**, every PCM and complete internal DSP snapshot equal to V4.4 baseline, including long idle, wake, effects and rare frame wrap.
- `tests/test_v39_pcm_reference.py`: **1,048,576 PCM bytes** match the historical 16-scenario golden reference.
- `tests/run_v39_quick_tests.sh`: PASS for existing rock/percussion/organ/saw and fixed point tests.
- `tests/native_v40_key_assign_leds.c`: PASS for persistent CHORD/KEY ASSIGN LED behavior.
- `tests/run_ota_v44_replay.py cc build/SikkenWorks-B1-V4.5-BEETLE-OTA.fwsc`: PASS, including an actual packet-level replay of the V4.5 package into the preserved V4.4 native updater, exact `0xE0000000` -> `success`, correct staged loader ID, and expected negative rejection cases. **This is not a physical flash result.**
- `tests/test_v45_artifacts.py`: PASS for hashes, embedded binary, protected header, source identifications and installer HF2 compatibility.

## Unverified on hardware

- Actual audio ISR **peak processing time** and DMA deadline misses on the physical JieLi CPU, especially three-voice attacks with rotary and percussion enabled.
- Actual improvement to measured CPU percentage, perceived crackle or user-perceived dynamics on physical FM1.
- Complete real-world bidirectional OTA/recovery after installing this release; V4.4 native OTA and SLOOP WebInstaller succeeded in simulation and limited prior user testing, not as a universal guarantee.

## Rebuild

```bash
export JIELI_TOOLCHAIN=/absolute/path/to/jieli-linux-toolchains-20250324.1
python tools/build_v45_release.py
```

Host tests must be run in a Linux environment with a working native compiler and Python. The external toolchain is not redistributed. The source ZIP includes the audited reference `.fwsc`, not a guarantee of unbricking a non-booting unit.
