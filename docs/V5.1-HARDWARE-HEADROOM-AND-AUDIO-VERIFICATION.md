# B1 V5.1 — lossless polyphony optimization and hardware headroom

Date: 2026-11-02. Permanent firmware identity: `FM-1_481026`.

## What actually changed

Only the `firmware/b1_engine.c` synthesis hot loop is changed functionally since V5.0. The default FM1 CPU-relief organ path calculates the same sine lookup directly instead of calling the general oscillator dispatcher for every wheel. In the steady dense mixer, there is a dedicated branch for LEAKAGE OFF. The existing transient shared-wheel prefetch takes the same exact shortcut when it is valid. All other synthesis methods, wheel phases and state updates are left intact. No FFT, sample-rate change, removed wheels/voices, approximation, gain change or new compressor.

`firmware/b1_main.c` had a version/physical-test comment updated only. Source MIDI identity, native OTA, USB descriptors, 256-frame DMA, live autosave and project storage are otherwise unmodified.

## Verified on host

- Native regression `tests/test_v51_lossless.py`: **96 + 128 + 96 = 320** scenarios are byte-for-byte identical for stereo PCM and complete `struct b1_engine` state compared to the original V5.0 source.
- 72 audio/FX/clipping combinations: pass with no hard 16-bit clipping.
- 48 single-block/two-block comparisons: bit-identical.
- DMA buffer size/deadline/underrun fade math: static/formula test pass.
- Native `.fwsc` UFW structure, CRC, application image, loader wrapping and package identity: pass.
- WebInstaller embedded `.fwsc` and SHA-256: byte-for-byte identical.
- Native OTA CHECK -> READ -> `success` -> stage/readback -> commit: two fixture replays pass (B1 and original BEETLE). Extended 16-case suite has not been run to completion in V5.1.

## Host throughput findings (NOT FM1 CPU measurements)

Repeated x86 host tests of a steady SAFE/ORGAN dense mix with 12 voices, all drawbars fully open and no effects:

- LEAKAGE OFF: V5.0 **155–168 ns/sample**, V5.1 **83–90 ns/sample** in the recorded runs.
- LEAKAGE ON: V5.0 **153–162 ns/sample**, V5.1 **102–107 ns/sample**.

These results are indicative only; different CPU instruction costs, cache effects, system load, timer and USB/MIDI interrupts on the actual pi32v2 can change the result. No real-hardware speedup percentage is claimed.

## Physical acceptance test, still required

The 60 MHz target has about 1361 processor cycles per 44.1 kHz audio sample before IRQ, input, USB, UI and effects overhead. The current 256-sample DMA half represents approximately 5805 µs, with a firmware hard budget of 5500 µs. For approximately 25% timing margin relative to the hard budget, target **PEAK <= 4125 µs** and **zero increments of DMA MISSES** at worst-case performance (12 voices, ORGAN/SAW, B3/ROCK, full drawbars, leakage/click/percussion and effects). A count of zero alone is insufficient if PEAK is too close to deadline.

1. Make a verified recovery backup; this OTA build is not guaranteed safe on every source firmware.
2. Open **SCL / SCALE → SELECT → AUDIO DIAG** on the FM1.
3. Observe PEAK and DMA MISSES after several minutes of 3, 6, 9, 12 notes, including repeated rapid note-on/off and long sustained chords.
4. Repeat in B3/ROCK and ORGAN/SAW, test key click/percussion/leakage, Leslie, scanner, delay and reverb at active settings; check headphones and line output for both underruns and analog overload.
5. If DMA MISSES rises, note the PEAK value and settings. Do **not** call it fixed; additional pi32v2-specific tuning is required. If MISSES stays zero but crackle persists, isolate output clipping/analog path with AUDIO DIAG test tone.
6. Separately verify The Firmware Hub B1 → compatible firmware → B1 round-trip before relying on cross-firmware OTA. Existing host checks are not a guarantee.

**Conclusion:** V5.1 provides a measured host performance improvement on the default SAFE/ORGAN mixer with exactly unchanged sound and state. Full twelve-voice real-FM1 headroom is NOT established until the physical worst-case test is completed.
