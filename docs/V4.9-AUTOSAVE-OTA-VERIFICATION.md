# SikkenWorks B1 V4.9 — native release verification

Date: 2026-10-23. This is a **software-only** build and replay report, NOT a physical FM1 test.

## Release and permanent identity

- Application SysEx and `.fwsc` product: **FM-1_481026**, unchanged from V4.8.
- Newly linked JieLi AC791N/pi32v2 application, packaged in original `.fwsc` container with exactly preserved BEETLE RC1.01 reference boot sector. That reference package is a build fixture, not B1's identity or a guaranteed hardware rescue path.
- The existing WebInstaller HF2 SLOOP/Felucca/stock menu, the 2-stage USB-MIDI protocol and protected OTA boot/staging paths are preserved. WebInstaller embeds the exact release binary and pins its SHA-256.
- Note: **The Firmware Hub's public documentation says identity collisions affect the displayed/selected firmware card, but do NOT by themselves prevent cross-firmware updates.** Real compatibility depends on the running native OTA CHECK path and the actual destination loader. Changing/relaxing the ID or all loader checks would be unsafe.

## Auto-save implementation (native, not browser-only)

- File changes: `firmware/b1_main.c`, `firmware/b1_storage.c/.h`, `firmware/b1_ui.c`.
- The 12 existing user-named project slots retain the exact byte offsets of V4.8 schema 2. A validated *live* `struct b1_project` and validity flag have been **appended** to the archive in schema 3 (1824 bytes, beneath the 4 KiB bank limit). V4.8 schema 2 and older V5 schema 1 are read without changing the old flash bytes at boot. The first new save uses the new schema.
- Parameters include all three registrations/drawbars, ORGAN/SAW, B3/ROCK settings, rotor/scanner/Leslie, percussion/key click/leakage, scale, range/chord assignments, delay, reverb, octave, etc. No active notes or in-flight FX state is saved.
- After any parameter edit: 5-second debounce; write only if different from last snapshot; 60-second minimum between flash-write attempts. The commit is deferred until there are no keys, voices, percussion or effect tails. Never autosave during OTA, USB recovery or a project transition.
- The original two-bank write-last commit record, full CRC32 validation, readback, safe-bank discovery and no-foreign-sector-erasure protections remain unchanged. Autosave does not reserve or erase additional sectors.
- REC recovery boot skips all normal project scanning/restoration and autosave. Power loss during the save leaves the previous committed bank available. `AUTO SAVED` is displayed briefly on the Projects page after a new commit.
- Like the existing manual project write, this pauses the codec and performs a ~330 ms silent re-prime. The prerequisite of total audio silence keeps that disruption away from played notes; **no independent on-device flash timing test is available**.
- Autosave cannot run if there are fewer than two B1-owned or verified blank sectors in `0xE7000..0xEFFFF`, or if the user never stops playing/effect tails never end. Do not assume every cross-firmware switch preserves an unrelated firmware's project sectors.

## Tests actually run

1. Native JieLi pi32v2 ELF build, FM1 image link, 610,086-byte `.fwsc` package structure, chip key, XIP, application CRC and product identity.
2. Native NOR flash journal regression: original **schema-2 V4.8** archive containing 12 saved projects, migration to schema 3 live snapshot, reboot restore, power-cut mid-write, rollback to last committed sector, unchanged named slots and unmodified foreign bytes.
3. Full earlier B1 regression suite (`tests/run_v03_tests.sh`), including old project-schema migration, key-chord, tonewheel and FX tests.
4. **96** exact PCM/DSP-reference cases with 1–12 voices; **72** maximum audio/effect host output cases; **48** DMA chunk consistency tests; audio engine source and scheduling unchanged from V4.8.
5. **16 native OTA packet-level replays of the exact production `firmware/ota.c`** with the newly built V4.9 `.fwsc`, original B1 V4.5, and an original pinned BEETLE RC1.01 package. Includes schema-consistent different loaders, differing protected boot header for APP_ONLY, early corrupted data/chip key, malformed/oversized loader, flash-readback corruption, missing `success`, abort, erase failure and malformed UFW overlaps. No flash commit for rejected cases.
6. WebInstaller HTML JavaScript syntax, native identity and complete embedded `.fwsc` bytes / SHA-256 parity.

## Tests NOT performed — blockers

- An **original Felucca v1.6 or 1.6.1 `.fwsc`** was identified online but could not be downloaded into the isolated build environment. The cross-firmware Felucca replay cases remain synthetic family variants, **not proof of compatibility with original Felucca release**. The BEETLE V1.4.14 source and official stock V15 firmware package were not available as verified local binary fixtures either.
- No physical FM1 flashing, no full The Firmware Hub B1 -> Felucca/BEETLE/V15 -> B1 round trip, no USB reconnect test, no flash wear/endurance measurement. The Hub cannot be guaranteed to accept **every** other firmware: unknown layout or loader must be rejected safely.
- Existing 3+ voice crackling, DMA overruns, and FM1 audio load were not measured or modified in V4.9. This release is storage/persistence and OTA-regression focused.

## Recommended physical acceptance

Back up all B1 and other-firmware projects and have the previously successful unbricker available. Install V4.9 with SLOOP HF2 installer, check identity `FM-1_481026`, change multiple parameters, release notes/let FX tails expire, wait at least 5 seconds, check project screen for `AUTO SAVED`, power cycle, and confirm every setting was recalled. Test one named project: it must remain unchanged when tweaking the live patch. For The Firmware Hub, try a trusted SHA-256-pinned compatible destination; record native OTA code/read-address sequence, loader identity after reset, and final app identity. Do **not** blindly repeat a failed flash.
