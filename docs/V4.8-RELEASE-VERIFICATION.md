# B1 V4.8 — Identity, OTA and polyphonic playback audit

## Original hardware symptoms

- A physical FM1 running V4.7 was identified as BEETLE by The Firmware Hub, refused direct changes to other firmwares, and only recovered through an independent unbrick path.
- Audible clicks/crackling were reported with three or more notes. Neither a captured DMA event log nor the FM1 hardware was available in this build environment.

## Corrected release artifacts

- New application SysEx / `.fwsc` identity: `FM-1_481026`. Previous B1 V4.7 `FM-1_2147` is intentionally **not** reused. All future B1 updates should keep this new identity.
- New `.fwsc` file is named `SikkenWorks-B1-V4.8.fwsc` to avoid identifying the actual B1 release with its BEETLE reference boot source.
- The SikkenWorks manufacturer and USB MIDI interface remain intact.
- Native AC791N/pi32v2 application built with the JieLi toolchain. Firmware SHA-256: `043340111c7acf1c4fbbed6f33daf9399ea1dba7ab6233017f1c200d79108fad`.
- WebInstaller embeds the same `.fwsc` byte-for-byte, pins that SHA-256, retains SLOOP HF2 source-device detection, and allows connection without Advanced Mode for `FM-1_900`.

## Native OTA code and caveats

- Audited `firmware/ota.c`, `firmware/b1_ota_target.c`, `firmware/usb.c` and firmware package identity.
- `APP_ONLY` checks chip `0x980F`, app flash `0x4000`, XIP `0x02000120`, app CRC and OTA loader CRC; foreign unused bootheaders are not falsely compared. The boot sector is not erased in app-only staging.
- Recognizes a structurally tagged, bounded Felucca-family loader, and rejects invalid bodies before staging. The *host* The Firmware Hub must pin package SHA-256; a family tag and CRC16 alone cannot authenticate executable machine code.
- Retains known loader and stock-V15 paths from the V4.7 code. Supports the incoming-loader variant path; 16 packet-level native replay cases cover BEETLE RC1.01, B1, synthetic Felucca-family loader changes, corrupted/mismatched packages, readback faults and missing success acknowledgement.
- Both `ota-FM-1_015` and `ota-FM-1_900` remain temporary handoff families. They are not the permanent application ID. Actual acceptance by The Firmware Hub after a physical reboot is still unverified.
- Cannot claim BEETLE V1.4.14 reference-identical: that exact snapshot and the actual original Felucca 1.6/1.1.5 firmware packages were not available as local binary fixtures.

## DMA / audio changes

- ALNK0 buffer changes from 128 frames / half to 256 frames / half at 44,100 Hz, reducing callbacks from approximately 344.53/s to 172.27/s. This trades up to ~2.90 ms of additional keyboard-to-output scheduling latency for more time between callbacks. It does not reduce the required per-sample DSP work.
- Stays in low-cost CPU relief default to preserve deadlines; 12 voice slots and all original effects remain, without changing oscillator or filter algorithms.
- The underrun fade uses widened 64-bit intermediate multiplication to prevent overflow at high DAC amplitudes. Overrun fade-out/next-block 64-frame crossfade prevent the abrupt direct all-zero buffer step when the half is still free. This can soften glitches but cannot restore missing audio once the DMA deadline has already passed.
- Host 72 combinations covering 1..12 voices, B3/ROCK, SAW/ORGAN, effects and all 9 drawbars: **no output hard-clip**. Host 48 configurations: rendering 256 frames at once is PCM-equivalent to rendering two blocks of 128 frames. No on-device CPU deadline measurements.

## Physical acceptance tests still needed

1. Back up the FM1 flash and all projects, prepare the proven independent unbricker recovery method.
2. Install B1 V4.8 using the bundled SLOOP HF2 WebInstaller; confirm `FM-1_481026` appears after reboot. The Hub may display an unknown name until its catalogue learns the ID.
3. Measure AUDIO DIAG `audio_misses` and `audio_peak_us` after 1, 3, 6 and 12 simultaneous notes with ROCK, delay/reverb and high drawbar settings. Record crackling and USB connectivity.
4. Only with original SHA-pinned destination packages, test **B1 -> supported Felucca -> B1**, **B1 -> BEETLE -> B1**, and V15 through the approved restore route. Verify every actual loader handshake and boot identity. No USB-unbrick should be needed after a healthy, compatible transition.
5. Any errors: export installer diagnostic log and record the displayed native OTA status / error and the firmware destination hash. Do not retry blind flash attempts.
