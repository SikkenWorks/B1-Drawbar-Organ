# B1 V5.4 — Native OTA / Polyphony verification

Date: 2026-11-02. **Software verification only; this release is NOT certified to return to stock V15/V16 from the actual FM1.**

## Deliverables and reproducibility

- Fixed application and FWSC identity: `FM-1_481026` (unchanged from V5.3).
- `.fwsc`: `build/SikkenWorks-B1-V5.4.fwsc`, 610,086 bytes, SHA-256 `2a8c9c24ac8214b44a3e818014c6f911e59f970a2165c2f20ff8543dd1d5650c`.
- Native `build/B1.elf` and `build/B1-app.bin`: compiled using JieLi pi32v2 toolchain `jieli-linux-toolchains-20250324.1` supplied in the build environment. Toolchain binary not redistributed in this ZIP.
- Installer `B1-WebInstaller.html` embeds the same exact FWSC and SHA-256. HF2/SLOOP connection fallback is retained, but NOT validated on physical hardware in V5.4.
- To reproduce: `JIELI_TOOLCHAIN=/path/to/jieli-linux-toolchains-20250324.1 python tools/build_v54_release.py`, then `python tests/test_v54_release.py` and `python tests/run_ota_v54_replay.py cc`.
- `fmhub.json` provides metadata for possible Hub registration. This does not enroll the firmware in The Firmware Hub and cannot add stock V16 to its remote catalog.

## Root-cause findings and code changes

1. `firmware/ota.c` stage reuse: previous B1 native OTA code returned `-15` whenever the reserved loader region was nonblank with a foreign but legitimate staged loader. A valid previous Felucca-family `LOADER.BIN` can now be reclaimed when **both** its JLFS wrapper and the pending OTA record validate and it is a known loader family. An unknown/invalid region is still never erased. This addresses *one reproducible cause* of B1 refusing another update, not all possible Hub/bootloader compatibility issues.
2. `firmware/ota.c` APP_ONLY layout: remove the byte-for-byte comparison against B1's own padded app slot size for a shorter, otherwise compatible target; CRC-verify the whole **declared target slot** with exact JieLi SFC XOR and retain the maximum app-flash bound, chip key, UFW CRC, app XIP and protected boot restrictions. A regression caught and corrected a bug where CRC checking initially still used the old fixed length.
3. All staged loader write/readback verification and the exact host eight-byte `success` confirmation remain mandatory before committing. Source uses version-tagged-compatible loader recognition; no unrestricted loader execution or full-flash wildcard.
4. `firmware/b1_engine.c`: move unchanged oscillator target and click-window choice out of the sample loop and skip now-expired contact-gate math when CLICK=0. The original DSP reference remains under `tests/reference_v53`. A proposed full nine-drawbar gain cache was benchmarked slower and removed. No voice/harmonic/function removal and no additional limiting.

## Stock firmware recovery status

- **V15:** a strict, SHA-pinned vendor FULL_FLASH restore branch was inherited and kept intact. A copy of the authentic M-VAVE V15 package is needed for an end-to-end native replay; it was not locally available as a raw original in this test session. Direct B1 V5.4 -> stock V15 through The Firmware Hub is **unverified**.
- **V16:** official M-VAVE firmware V16 (`FM-1_016`, first published 2026-10-21) uses a **different** stock update package. The authentic binary is not available in the local test environment; it was therefore **not** put on B1's stock allowlist or routed through its V15-specific full-flash path. B1 V5.4 -> V16 via The Firmware Hub is **not yet supported/proven**. Claiming always-safe V16 support would be unsafe without checking its bootloader and flash map.
- Hub catalog and supported stock destinations are controlled externally. B1 source/`fmhub.json` cannot force stock V16 to appear as a Hub action.
- Use only original verified vendor packages and keep independently confirmed USB rescue available before upgrading. Back up project/patch data: vendor stock firmware may overwrite custom storage.

## Audio hardware acceptance criteria NOT YET MET

The real FM1's `SCL -> SELECT -> AUDIO DIAG` must show **0 DMA MISSES** throughout repeated 3/6/9/12-note chords with all nine drawbars open, and worst render PEAK below the real-time buffer deadline (target <= 4.1ms of the 5.5ms budget for approximately 25% margin). Also listen for clipping at the headphone output and compare effect on/off. Neither device CPU cycles nor acoustic crackle are measurable from host PCM tests. **It is NOT demonstrated that V5.4 fixes the reported crackling.**
