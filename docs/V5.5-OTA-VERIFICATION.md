# B1 V5.5 — Native OTA interoperability and original V15 recovery audit

Date: 2026-11-02. **JieLi binary built and native protocol replays passed; real FM1 / original vendor V15 end-to-end is not yet confirmed.**

## Diagnosis confirmed in V5.4 native code

1. `firmware/ota.c::ota_ufw()` hard-rejected `nent != 2` (`-2`). The original official M-VAVE V15 `.fwsc` contains **eight** UFW directory entries (the community B1/BEETLE packages have two). This categorically prevented stock V15 CHECK from proceeding.
2. Prior stock validation used a SHA-256 for the complete 0x93000-byte `flash.bin` that was not independently verifiable from public source; the widely documented `6edf3c37…` digest is of **only** `flash.bin[0x4000:0x93000]` (0x8f000 bytes), not the full flash image. These values MUST NOT be compared as if they covered the same data.
3. V5.4's existing `-15` staged-loader ownership and Felucca family validation remain intact in V5.5; stock support must not bypass or weaken them. The fixed product/USB identity is `FM-1_481026`.

## Production changes

- `ota_ufw` explicitly accepts either community 2-entry or vendor **8-entry** packages. Vendor 8-entry mode requires precisely `flash.bin`, `info.log`, `USR`, `isd_config.ini`, `ota.bin`, `script.ver`, `blimit.bin`, `tail.bin`, each exactly once. Directory bounds, offsets, nonoverlap, entry length and whole UFW header/list CRC are checked before any flash erasure. All eight individual payload CRCs are also checked.
- Stock V15 mode requires the exact vendor loader length `0x4de1`, outer vendor header CRC `0xebaa`, outer data CRC `0x5881`, the existing nested loader header integrity, and the exact known V15 application SHA-256 on the **correct** 0x8f000-byte logical flash slice.
- An independent SHA-256 check reconstructs the raw **699,956-byte** `FM-1_015` `.fwsc` from the logical host read stream (including its twenty identity marker bytes) and compares it to exact **official vendor SHA-256** `db1642b2b6fa5c2cccb11ffd13878068bb28601678d3644049f99dc40e7edb8a`. This means only that original package can use the FULL_FLASH path; arbitrary 8-entry packages remain rejected.
- Store all validated UFW ownership metadata solely in RAM; do not claim new flash or overwrite app, project, settings, boot, calibration or recovery areas during native CHECK. Only after full validation does the existing OTA stage/verify/success/commit sequence execute.
- Stage the original authenticated vendor loader into the original reserved OTA area and preserve `ota-FM-1_015` as its temporary identity. The normal B1 identity stays `FM-1_481026`.
- No changes to the audio/engine, autosave, existing project storage, USB transport, controller UI or other features.

## Native tests actually executed

- JieLi pi32v2 compile, firmware `.fwsc`, WebInstaller embedded bytes and SHA-256 check: PASS.
- 18 existing native CHECK/commit replays with B1/BEETLE sources, valid/invalid Felucca-style versions, malformed application, wrong key, aborted/missing `success`, corrupt flash readback and staging-owner edge cases: PASS.
- Vendor 8-entry **synthetic** protocol replay: production rejects fake vendor stock before erase `-26` (PASS); corrupted auxiliary file rejected `-25` (PASS); UFW overlap rejected `-3` (PASS); valid synthetic vendor loader and app with a **test-only compiled digest override in a TEMPORARY ota.c copy** goes through full host CHECK -> `success` -> vendor-stage/readback -> `ota-FM-1_015` -> commit (PASS). The release `firmware/ota.c` contains no test bypass.
- 96+128+96 reference tests comparing PCM and entire engine state bit for bit against V5.3, 72 audio stress runs, 48 DMA buffer/continuity checks, saved AUTO SAVE OFF/ON and persistence tests: PASS (unchanged audio).
- Optional `python tests/run_ota_v55_original_stock.py /path/to/FM-1.fwsc` is provided to execute the exact production native CHECK with the **real SHA-pinned original V15**, once the user supplies it. Do not confuse the synthetic replay with a result from that original binary.

## What remains unproven

1. The original **M-VAVE V15** `.fwsc` was not accessible to this execution environment. Therefore its complete native replay and correct OTA loader re-enumeration are still unverified here.
2. A physical FM1 (B1 V5.5 -> The Firmware Hub -> stock V15 -> B1 V5.5) has not been exercised in this session. The exact stock loader writing boundaries / effects on settings need an on-device test with verified recovery.
3. Stock V16 is a separate vendor firmware not included in the Hub's verified V15 route. V5.5 does NOT grant arbitrary V16 FULL_FLASH permission.
4. B1 V5.4, already installed, cannot be repaired remotely without first installing V5.5 through a route that its old updater permits. Use known-good firmware/recovery tools and back up the device first.
5. Audio polyphony crackling has **not** been changed or solved in V5.5. Physical `AUDIO DIAG` measurements remain needed.


The original stock firmware is **not redistributed** inside this ZIP. Verify the full package's SHA-256 with the authoritative published checksum before testing. An OTA CHECK success in a simulator is not proof of reliable on-device flashing or recovery.
