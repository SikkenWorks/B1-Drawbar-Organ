# B1 V4.7 — Firmware Hub handoff / clean-polyphony performance verification

## Identity policy

- Application/package identity: `FM-1_2147`, **identical to V4.6**.
- USB product string `FM-1` (generic MIDI port), manufacturer `SikkenWorks`. USB class, VID/PID and SysEx identity are unchanged.
- Loader-stage identity is *not* the application identity: original pinned writer `ota-FM-1_015`, versioned Felucca-family writer `ota-FM-1_900`. Not proof of support for every firmware family.

## Changes and root cause

- V4.6 allowed a new foreign loader but always wrote the original temporary identity `ota-FM-1_015` into the 112-byte update record. This is inconsistent with a separately staged Felucca writer; its handshake could be misclassified as an official/V15 loader.
- The vendor/product USB string descriptors in V4.6 still read `ETCH`; they now identify SikkenWorks and keep the standard `FM-1` port naming.
- On key press V4.6's DSP loop scanned 12 voice slots and all 9 harmonics each sample even when inactive; V4.7 precomputes the active notes/harmonic mask and keyclick delays, with exact integer arithmetic retained.

## Proven tests

- Native pi32v2 JieLi compiler/ELF/app.bin build completed.
- `.fwsc` size 610086 bytes, SHA-256 `a07ca7b6cb67ff2412bff6a60c1789450bd10e9240b7c2aee3f1201dc2729650`. Package integrity and app CRC verified by `tools/fm1_fwsc.py`.
- 96 polyphony tests (1–12 voices x 8 configurations): PCM and all engine state **byte-identical** to B1 V4.6.
- Native OTA packet-replay of original B1 and BEETLE RC1.01 `.fwsc` plus 14 synthetic negative/variant tests. Different staged family loader uses `ota-FM-1_900`; stock/pinned loader uses `ota-FM-1_015`.
- Installer embeds the exact V4.7 firmware bytes and checksum, retains HF2 SLOOP compatible browser path.

## Still unproven

- Actual Firmware Hub A → B1 V4.7 → B on physical hardware, USB re-enumeration in real hardware and stock V15 restore.
- Whether the Hub labels `FM-1_2147` as BEETLE due to shared catalogue identity. The hub controls labels, not B1's USB manufacturer string. No product ID change was made.
- CPU usage and full 3–12 voice click-free playback on FM1. DSP output identity validates correctness but target deadlines require real measurements.
- Original Felucca 1.6 `.fwsc` was not locally available for native packet-level replay; synthetic valid package variants do not prove it.

## Test on the FM1

Back up projects, confirm your independent rescue route. Install V4.7. After reboot use AUDIO DIAG and test 1/3/6/12 note chords with drawbars at 8, with ROCK/rotor/delay/reverb. Record `audio_misses` delta and `audio_peak_us` after a reboot. Do not experiment with unknown cross-firmware images until exact package and loader handshake are independently verified.

## Host workload proxy (not a hardware CPU percentage)

A C `-O2` desktop benchmark with 3 notes repeatedly retriggered, ROCK, click, leakage and partial registrations measured **about 170 ns/sample in the V4.6 reference versus 154 ns/sample in the optimized V4.7 DSP** (~9% lower host render time in that pattern). Run `tests/bench_v47_host_audio.c` against `tests/reference_v46/b1_engine.c` and `firmware/b1_engine.c`. Target pi32v2 performance, 10 kHz interrupt load and hardware DMA misses remain unknown. Different compilers and cache hierarchy may change the result.

The original app source references BEETLE as a boot package foundation. This does not turn the user-facing B1 firmware into BEETLE; however, The Firmware Hub maps its display label using the identity register, which cannot be changed while retaining `FM-1_2147`.
